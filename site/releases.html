진행 기록

헛걸음 제로가 달라진 점을 모았습니다. 자세한 측정과 실패 기록은 PLAN.md 의 진행 기록에 있습니다.

0.10.02026-09-27

  • 안드로이드 앱(APK)을 만들었습니다. 대회 제출물(설치 파일)로, 웹앱과 같은 기능을 그대로 담고 우리 아이콘·시작 화면·출시용 서명을 붙였습니다.

에뮬레이터(안드로이드 16)에서 지금 목록·조회·QR 카메라·내 위치 동선·재생·현장 조사→클라우드 DB·구조대 확인→클라우드 DB·사진 찍기·인터넷 없이 열기·뒤로 가기를 하나씩 확인했습니다.

  • 고친 것: 안드로이드에서 '사진 찍기' 가 카메라 대신 앨범만 열던 것(안드로이드 11+ 선언), 뒤로 가기가 어느 탭에서든 앱을 닫던 것.
  • 클라우드 갱신이 늦어져도(GitHub 이 예약을 건너뜀) 3시간 안의 목록은 "갱신이 늦어지고 있어요" 와 함께 보여 줍니다. 전에는 45분이 지나면 6월 시연 자료로 돌아갔습니다.
  • 대회 제출 zip 도구와 출처 증명 폴더, 참가신청서 작성본.

0.9.02026-09-26

  • 앱이 어디서든 돕니다. 실시간 경보를 맥 대신 GitHub 에서 10분마다 계산하고(맥이 꺼져 있어도), 앱과 웹앱은 밖에서도 '지금' 목록과 매일 아침 목록을 받습니다.
  • 구조대 확인·현장 조사가 클라우드 DB 로 바로 갑니다(Supabase). 앱 키로는 넣기만 되고, 남의 기록은 읽을 수 없으며 자전거별 확인 수만 보입니다. 위치·메모·사진은 운영자만 봅니다.
  • 지난(시연) 자료를 보고 있으면 분명히 알려 줍니다. 전에는 밖에서 번호를 조회하면 6월 자료로 "연쇄 없음 ✓" 이 떠 오해할 수 있었습니다.
  • 맥이 잠들었다 깨면 빠진 시간을 채우고, 아침 목록도 덜 받은 시간부터 다시 받습니다.
  • 전기차 충전기 상태도 GitHub 에서 모읍니다(바뀐 상태만 저장). 검증은 빈틈없이 이어 찍은 구간 안에서만 연쇄를 잇습니다.
  • 실시간 대여소 현황을 2,747곳 모두 받습니다(전에는 1,000곳에서 멈춤).
  • MIT 라이선스.

0.8.22026-09-25

  • 전기차 충전기 숫자를 바로잡았습니다. 첫날 "끝난 충전의 7.7~8.2% 가 3분 안에 끊김" 이라고 적었는데, 고장이 아닌 기록이 섞여 있었습니다.

어떤 사업자는 충전 중인데도 5분마다 '0초 충전' 을 남기고, 어떤 사업자는 전체 충전의 40~75% 가 3분 안에 끝납니다(충전기 수백 대가 한꺼번에 고장일 리 없음).

0초 기록과 이런 사업자를 뺀 뒤(57곳 중 39곳, 충전의 76% 남김) 3분 안에 끊긴 충전은 3.3% 입니다.

  • 중간 검증 docs/ev_validation.md (analysis/ev_validate.py): 헛충전 한 번 뒤 다음 충전도 헛충전 19% (31건 중 6건, 평소 3.3%). 아직 표본이 작아 판정 전 — 1~2주 모아 연쇄 2 뒤 100건 이상에서 판정합니다.

0.8.12026-09-25

  • 서울 자료가 늦을 때 알립니다. 9월 25일 14시부터 대여이력 API 가 한 시간에 평소의 2~5% 만 내놓았습니다(비 없음). 그동안 새 경보를 놓치는데 화면은 멀쩡해 보였습니다.

이제 시간마다 지난 7일 같은 시각 중 가장 한산했던 날과 견줘 30% 도 안 되면 '모자란 시간' 으로 보고, 앱에 "서울시 대여 기록이 N시부터 평소의 M%만 올라오고 있어요" 를 띄웁니다.

  • 모자란 시간은 48시간 동안 10분마다 다시 받아, 서울시가 뒤늦게 채우면 경보와 채점이 저절로 바로잡힙니다.
  • 경보와 다음 대여 사이에 모자란 시간이 끼면 채점을 보류합니다(빠진 대여가 진짜 다음 사람일 수 있어서).
  • 추석(9/24~26) 아침처럼 진짜로 한산한 시간은 모자란 시간으로 치지 않습니다(평일 중앙값의 22~25% 지만 주말 아침과는 비슷).
  • 소개 사이트·README 의 "누구에게 도움이 되나" 를 다시 정리했습니다: 정비 쪽이 먼저, 관광객·어르신은 공식 앱에 들어갈 때, 구조대는 검증 도구.
  • 고친 것: 아이폰 조회가 실시간 목록에서도 "어제까지" 라고 하던 것.

0.8.02026-09-25

  • 정비 동선을 '가장 많이 막는 동선' 으로 바꿨습니다. 근무 시간(1시간·1시간 반·3시간)을 고르면, 그 안에 헛걸음을 가장 많이 막을 대여소와 도는 순서를 고릅니다(오리엔티어링 문제). 대여소마다 도착 예상 시각과 막을 헛걸음 예상을 보여 줍니다.

  • 웹앱과 아이폰 앱이 같은 풀이로 같은 답을 냅니다(검사로 확인).
