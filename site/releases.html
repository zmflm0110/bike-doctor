진행 기록

헛걸음 제로가 달라진 점을 모았습니다. 자세한 측정과 실패 기록은 PLAN.md 의 진행 기록에 있습니다.

0.7.02026-09-25

  • 디자인을 부드럽고 친근하게 바꿨습니다. 의심 자전거 하나가 게시물 하나(큰 숫자 카드, '3초 확인'·'자세히' 단추), 구는 동그란 고리로 고르고, 아래 탭은 아이콘(홈·조회·확인·재생·조사), 재생은 어두운 화면 위 큰 시계. 색은 우리 청록.
  • 웹앱과 아이폰 앱이 같은 모양입니다. 아이폰 앱은 맥의 Xcode 27 로 직접 빌드하고 시뮬레이터에서 확인했습니다.
  • 소개 웹사이트도 둥근 단추·고리 모양 바로가기로 부드럽게 했습니다.
  • 고친 것: 아이폰 앱에서 숫자를 끼워 넣은 굵은 글씨가 ** 로 그대로 보이던 것, 화면 검사가 검정 바탕을 투명으로 잘못 보던 것.

0.6.02026-09-25

  • 실시간 경보를 켰습니다. 서울 대여이력 API 가 자전거별 기록을 반납하자마자 준다는 걸 확인하고(지연 약 0분), 1분마다 경보를 내는 서버를 돌립니다.
  • 같은 날(6월 15일)을 API 와 월별 공개 파일로 받아 맞춰 봤습니다. 대여 150,830건과 150,827건이 모두 짝을 이루고, 헛대여·다음 날 아침 목록 79대가 같았습니다.
  • 경보마다 "다음에 빌린 다른 사람도 바로 반납했나" 를 스스로 채점합니다.
  • 정확도의 두 정의를 모든 문서에 나눠 적었습니다: 경보 한 건마다 다음 사람 기준 32~34%, 경보가 켜진 동안 빌린 모든 사람 기준 52~60%.
  • 웹앱과 아이폰 앱에 '지금 (실시간)' 목록을 넣었습니다. 운영 목록은 신고 자료가 없어 신고 여부를 '모름' 으로 보여 줍니다.
  • 전기차 충전기 상태를 5분마다 모으기 시작했습니다.
  • 작품 소개 웹사이트와 시연용 웹앱을 공개했습니다.

0.5.02026-09-25

  • 아이폰 앱(SwiftUI) 다섯 탭을 만들고, 맥 CI 에서 Xcode 빌드와 시뮬레이터 실행을 확인했습니다. 엔진은 웹앱과 같은 답을 내는지 검사합니다.
  • 정비 동선(내 근처 10곳을 도는 순서), 구 고르기, 엑셀용 CSV 를 넣었습니다.
  • 접근성: 탭 역할, 입력칸 이름표, 화면 읽기 알림, 글자 대비 4.5:1 검사.
  • 시연 영상을 자동으로 녹화하고, 발표·보고서·서울시설공단 제안서 PDF 를 만들었습니다.
  • 맥에서 매일 아침 목록·웹 서버가 저절로 돌게 했습니다(launchd).

0.4.02026-09-24

  • 오프라인 시연을 고쳤습니다. 지도 라이브러리를 앱 안에 넣고, 본 적 있는 지도 조각만 저장하고, 조각이 없어도 대여소 점으로 서울 모양이 보입니다.
  • 집 와이파이 안에서만 쓰는 https 를 준비했습니다(아이폰 위치·QR).
  • 현장 조사 탭과 검증 스크립트(95% 신뢰구간)를 만들었습니다.
  • 과장을 하나 고쳤습니다: 헛대여 모양으로 고장 종류를 한 대씩 맞히면 10~14% 만 맞아, 종류는 사람이 확인합니다.

0.3.02026-09-24

  • 매일 아침 목록을 운영과 같은 코드로 7일 연속 예행연습했습니다. 목록 자전거를 그날 처음 빌린 사람의 42.3% 가 또 헛걸음했습니다.
  • 생년·성별이 없는 자료에서도 되게 했습니다: "반납 2분 안에 다시 빌리면 같은 사람" 으로 대신해도 정밀도 차이 0.2%p.
  • 웹앱 첫 판: 아침 목록, 자전거 조회(QR), 구조대, 하루 재생 시연.

0.2.02026-09-24

  • 공개 실시간 대여소 대수로 경보를 낼 수 있는지 시험했습니다. 정밀도 0.2~1.7% 라 쓸 수 없어 하루 늦은 아침 목록으로 물러섰습니다. (0.6.0 에서 자전거별 대여이력 API 를 찾아 뒤집었습니다.)

0.1.02026-09-24

  • 엔진과 검증: 규칙(3분·300m·서로 다른 사람 2연속)을 2026년 1월 기록으로만 정하고 3·6월과 대전 타슈에 그대로 적용했습니다. 5개월, 약 1천만 건.
  • 서로 다른 두 사람이 포기한 자전거는 다음 사람도 35~44% 가 포기합니다(평소 2.5~2.9%).
