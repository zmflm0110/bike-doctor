# 발표 구성 (7분 기준, 10장) — 슬라이드 초안과 말할 거리

1. **표지** — "헛걸음 제로: 앞사람들의 헛걸음이 고장을 알려 준다". 이름·학교.
2. **장면** — (사진) 따릉이 QR 을 찍고, 체인이 헛돌아 바로 반납하는 모습. "이 자전거, 제 앞에서도 두 명이 똑같이 포기했습니다. 기록엔 다 남아 있었어요."
3. **문제** — 고장 신고 매년 10만 대+, 불만 1순위. 공단은 **신고가 있어야** 안다. 사람들은 **귀찮아서 신고하지 않는다.**
4. **아이디어** — 헛대여 = 3분·300m 안 반납. 한 번은 우연, **서로 다른 사람이 연달아** 면 자전거 탓. (그림: 자전거 한 대의 하루 타임라인, 포기-포기-포기)
5. **증거 1** — `fig_chain.png`: 앞선 포기 0명 2.5% → 2명 35\~44% → 4명 약 70%. 두 도시·다섯 달·약 1천만 건에서 같은 선. "우연이 아닙니다."
6. **증거 2** — 신고보다 20\~25시간 빠르다, 그 사이 평균 3.5\~4.6명 헛걸음. 연속 헛대여의 절반 이상은 1주일 뒤에도 신고 없음.
7. **실시간 — 두 번 뒤집힌 결론** — 대여소 대수만으로는 안 된다(정밀도 2% 미만, 직접 재서 확인) → 한때 아침 목록으로 물러섬. 그런데 서울 대여이력 API 는 자전거별 기록을 **반납 즉시** 준다. 6/15 하루를 API·월별 파일로 대조: 대여 150,830/150,827, 헛대여 4,087/4,085, 다음 날 목록 79대 같음 → **실시간 경보**가 지금 1분마다 돈다. 교훈: "안 된다" 전에 공개 API 목록부터.
8. **시연** — 앱 화면: 아침 목록 위 "이 목록은 맞았을까?"(6/15 목록 뒤 첫 이용자 77명 중 29명, 38% 또 반납) → 조회에 SPB-69683 → "서로 다른 28명이 바로 반납" 경고 → 시연 탭 재생(지도에 경보·막은 헛걸음이 쌓임). 영상 `docs/demo/demo.mp4`.
9. **함께 고치기** — 정비 기사는 구를 골라 목록·도는 순서·엑셀 CSV. 구조대: 경보 뒤 다음 대여까지 30분, 그 사이 같은 대여소 이용자 2명 → 3초 확인으로 정비까지. 현장 조사 결과(Phase 5 뒤 채움).
10. **넓히기·마무리** — 대전 타슈 검증 완료, 전기차 충전기 "헛충전"(권익위 민원주의보 2026), 다른 도시. "신고를 기다리지 말고, 흔적을 읽자."

## 예상 질문
- *그냥 마음이 바뀐 거 아니에요?* → 그래서 한 번이 아니라 **서로 다른 사람의 연쇄**. 0명→2명이면 14배.
- *같은 사람이 여러 번 빌린 거면?* → 생년·성별이 같은 연속 대여는 한 사람으로 센다(거르면 오히려 신호가 강해짐).
- *실제로 고장인지 어떻게 알아요?* → 고장 신고와 대조(신고보다 20시간 빠름) + 현장 조사(보고서 9장).
- *실시간이 안 되면 쓸모가 있나?* → 아침 목록만으로 하루 34\~70명의 헛걸음, 그리고 신고 안 된 고장 66\~82% 를 찾는다.
- *정비 기사는 이걸 어떻게 써요?* → 구를 고르면 그 구의 의심 자전거, 도는 순서(직선거리), 엑셀 CSV. 구조대·현장 조사로 사람이 본 고장이 순위 맨 위.
- *운영하면 정말 매일 되나요?* → 매일 06:10 자동(맥 launchd), 다음 날 아침 어제 목록을 스스로 채점해 앱에 보여 줌. 가짜 API 로 이틀 연속 예행연습 테스트.
