# 서울시설공단 제안서 (초안) — 대여기록으로 신고되지 않은 따릉이 고장을 찾기

> 요청 한 가지: 이미 공개된 **자전거별 실시간 대여이력(서울 열린데이터광장 tbCycleRentData)** 으로 저희가 켜 둔 **실시간 고장 의심 경보**를, 한 구(區)의 정비 현장에서 2주만 써 보고 맞았는지 알려 주세요. 자료·알고리즘·앱은 준비되어 있고 비용은 없습니다.

## 1. 무엇을 찾았나
- 같은 대여소에 **3분 안에, 300m 도 안 가고** 반납한 대여(헛대여)가 **서로 다른 사람**에게서 두 번 이어진 자전거는, 다음 사람도 **35~44%** 가 바로 반납합니다(평소 2.5~2.9%, 약 14배).
- 서울 2026년 1·3·6월(약 875만 건)과 대전 타슈 2025년 5·10월(약 122만 건)에서 같은 결과. 기준은 1월로만 정하고 다른 달·도시에 그대로 적용했습니다(경보가 켜진 동안 빌린 사람 중 또 헛걸음 51.8~60.2%, 1월과 차이 ±2.3%p 이내 · 경보 한 건마다 다음 다른 사람 기준 32~34%, 평소의 약 13배).

## 2. 공단에 도움이 되는 점
| | 결과 (공개 자료 기준) |
|---|---|
| 고장 신고보다 빠름 | 경보 → 신고 중앙값 **20~25시간**, 그 사이 한 자전거에서 평균 3.5~4.6명 헛걸음 |
| 신고 안 되는 고장 | 서로 다른 사람의 연속 헛대여 중 **49~61%** 는 7일이 지나도 신고 없음 |
| 매일 아침 점검 목록 | 어제까지 기록만으로 하루 45~78대, 그날 첫 이용자 34~42% 가 헛걸음, 그중 66~82% 는 아직 미신고 |
| 정비 동선 | 경보의 절반이 대여소 16.2% 에 몰림 → 먼저 볼 대여소 순위 |
| 고장 종류 | 평균으로는 단말기 헛대여가 짧음(중앙값 13초, 타이어·체인 37~38초). 하지만 한 대씩 '단말기' 로 맞히면 10~14% 만 맞아 **이름표로는 쓰지 않고**, 종류는 구조대·정비 확인으로 받음 |
| 막을 수 있던 헛걸음 | 서울 하루 90~243명 |

## 3. 실시간으로 되는 이유
대여소별 **대수**만 주는 실시간 대여정보로는 경보가 0.2~1.7% 만 맞았습니다(남의 평범한 대여·반납과 구분이 안 됨).
하지만 서울 열린데이터광장의 **대여이력 API(tbCycleRentData)** 는 자전거 번호가 있는 기록을 **반납하자마자** 줍니다(2026-09-25 실측 지연 약 0분).
같은 날(6/15)을 이 API 와 월별 파일로 받아 보니 행·헛대여·아침 목록이 모두 같아, 파일로 잰 정확도가 실시간에도 그대로 섭니다.
→ **서로 다른 두 번째 사람이 바로 반납하는 그 순간** 경보를 켤 수 있고, 저희 서버가 1분마다 그렇게 하고 있습니다.

## 4. 제안
1. **(시범, 비용 없음)** 실시간 경보와 "아침 점검 목록" 을 한 구(區)의 정비 담당에게 2주간 드리고(앱에서 구를 골라 엑셀용 CSV·도는 순서까지), 실제 고장 여부를 확인해 주시면 정확도를 함께 측정.
2. **(연계)** 경보가 켜진 자전거를 정비 대상에 바로 올리거나 잠시 대여 중지 — 경보 뒤 다음 사람의 헛걸음을 막는 가장 빠른 길.
3. **(앱)** 따릉이 앱의 자전거 선택 화면에 "최근 서로 다른 N명이 바로 반납" 표시 — 이용자 스스로 피하게.

## 5. 한계 (솔직하게)
- "고장" 의 정답 자료가 없어 **다음 사람의 헛걸음**을 주 지표로 썼습니다. 현장 조사로 실제 고장 비율을 확인하는 중입니다.
- 아무도 빌려 보지 않은 고장은 기록에 흔적이 없어 찾을 수 없습니다.
