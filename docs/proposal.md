# 서울시설공단 제안서 (초안) — 대여기록으로 신고되지 않은 따릉이 고장을 찾기

> 요청 한 가지: **자전거별 대여·반납 기록을 실시간(또는 1시간 단위)으로 쓸 수 있게 해 주시면**, 이용자가 빌리기 전에 고장 의심 자전거를 피하게 할 수 있습니다. 알고리즘과 앱은 준비되어 있습니다.

## 1. 무엇을 찾았나
- 같은 대여소에 **3분 안에, 300m 도 안 가고** 반납한 대여(헛대여)가 **서로 다른 사람**에게서 두 번 이어진 자전거는, 다음 사람도 **35~44%** 가 바로 반납합니다(평소 2.5~2.9%, 약 14배).
- 서울 2026년 1·3·6월(약 875만 건)과 대전 타슈 2025년 5·10월(약 122만 건)에서 같은 결과. 기준은 1월로만 정하고 다른 달·도시에 그대로 적용했습니다(정밀도 51.8~60.2%, 1월과 차이 ±2.3%p 이내).

## 2. 공단에 도움이 되는 점
| | 결과 (공개 자료 기준) |
|---|---|
| 고장 신고보다 빠름 | 경보 → 신고 중앙값 **20~25시간**, 그 사이 한 자전거에서 평균 3.5~4.6명 헛걸음 |
| 신고 안 되는 고장 | 서로 다른 사람의 연속 헛대여 중 **49~61%** 는 7일이 지나도 신고 없음 |
| 매일 아침 점검 목록 | 어제까지 기록만으로 하루 45~78대, 그날 첫 이용자 34~42% 가 헛걸음, 그중 66~82% 는 아직 미신고 |
| 정비 동선 | 경보의 절반이 대여소 16.2% 에 몰림 → 먼저 볼 대여소 순위 |
| 고장 종류 | 평균으로는 단말기 헛대여가 짧음(중앙값 13초, 타이어·체인 37~38초). 하지만 한 대씩 '단말기' 로 맞히면 10~14% 만 맞아 **이름표로는 쓰지 않고**, 종류는 구조대·정비 확인으로 받음 |
| 막을 수 있던 헛걸음 | 서울 하루 90~243명 |

## 3. 왜 공단 자료가 필요한가
공개 실시간 API 는 대여소별 **대수**만 줍니다. 과거 기록으로 30초마다 찍은 것처럼 재현해 보니, 대수 변화만으로 잡은 경보는 **0.2~1.7%** 만 맞았습니다(다른 사람의 평범한 대여·반납과 구분이 안 됨).
→ 자전거 번호가 있는 기록이 있어야 합니다. **한 시간 단위로만 열려도** 아침 목록을 하루 여러 번 갱신할 수 있습니다.

## 4. 제안
1. **(시범, 비용 없음)** 공개 월별 파일로 만든 "아침 점검 목록" 을 한 구(區)의 정비 담당에게 2주간 보내 드리고(앱에서 구를 골라 엑셀용 CSV·도는 순서까지), 실제 고장 여부를 확인해 주시면 정확도를 함께 측정.
2. **(자료)** 자전거별 대여·반납 기록의 실시간 또는 1시간 단위 제공(내부 API 또는 공공데이터포털). 개인정보(생년·성별)는 필요 없습니다 — "반납 2분 안 재대여 = 같은 사람" 으로 대신해도 정밀도 차이 0.2%p 이하.
3. **(앱)** 따릉이 앱의 자전거 선택 화면에 "최근 서로 다른 N명이 바로 반납" 표시 — 이용자 스스로 피하게.

## 5. 한계 (솔직하게)
- "고장" 의 정답 자료가 없어 **다음 사람의 헛걸음**을 주 지표로 썼습니다. 현장 조사로 실제 고장 비율을 확인하는 중입니다.
- 아무도 빌려 보지 않은 고장은 기록에 흔적이 없어 찾을 수 없습니다.
