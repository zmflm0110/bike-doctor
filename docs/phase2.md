## 결론
- **공개 실시간 API(대여소별 대수)만으로는 안 된다.** 30초마다 찍어도 헛대여의 54% 만 깜빡임으로 보이고, 깜빡임의 87% 는 다른 사람의
  평범한 대여·반납이다. 대여소 경보 중 진짜는 0.2~1.7% — 쓸 수 없다. (붐비는 대여소일수록 나쁨)
- 대안 = **하루 늦은 자전거별 기록**(`phase2_nextday.py`, 결과 `phase2_nextday.md`): 아침마다 어제 자정까지의 기록으로
  "연쇄가 끊기지 않은 자전거" 목록 → 하루 45~78대, 오늘 첫 이용자 헛걸음 34~42%, **그중 66~82% 는 아직 고장 신고 없음.**
- 실시간 이용자 경고는 **공단의 자전거별 실시간 자료**가 있어야 한다 → 발표의 제안: "공단이 켜기만 하면 된다".
- **(2026-09-25 뒤집힘)** 서울 대여이력 API(tbCycleRentData)가 바로 그 자전거별 기록을 반납 즉시 공개하고 있었다. 이 결론은 대여소 대수 API 만 보고 낸 것 → `docs/api_parity.md`, `server/live.py`.
