# RIDEY 스토리라인 — 수상용 (2026-10-03)

> 발표(본심 6분)·작품 설명서(예심)·시연 영상(2분)이 **같은 이야기**를 하게 맞춘다. 숫자는 모두 근거 문서가 있다(괄호).
> 심사: 기획 25 · 개발 45 · 디자인 20 · 시연·발표 10.

## 한 문장
**사람들은 고장 신고는 안 하지만, '빌리자마자 반납' 으로 이미 신고하고 있었다. RIDEY 는 그 흔적을 읽어 고장 자전거를 신고보다 하루 먼저 찾는다.**
마지막 말: **신고를 기다리지 말고, 흔적을 읽자.**

## 주인공 셋
1. **SPB-69683** — 실제 자전거 한 대 (서울 6월 대여이력, `data/raw` · 고장신고 내역)
2. **출근길 이용자** — 이 자전거 앞에서 시간을 잃은 73명 중 한 사람
3. **공단 순회 직원** — 하루 한 번 대여소를 돌지만 "멀쩡해 보이는" 고장은 눈으로 못 본다 (`docs/operations.md`)

## 1막 — 잃고 있는 것 (약 1분 30초, 발표 1\~3장)
**장면: SPB-69683 의 12일** (강서구, 실제 기록)
- 6월 12일 14:56 — 마지막으로 누군가 제대로 타고 와 '힐스테이트에코' 대여소에 반납
- 15:20 — 첫 사람이 빌리자마자 반납. **15:43 — 두 번째 사람도.** ← RIDEY 라면 이때 경보
- 6월 13일 07:58 — 첫 고장 신고(타이어). 16시간 뒤
- 그런데도 그 뒤 **54번 더** 빌렸다가 바로 반납. 6월 16일 아침 7:13\~7:50, 등촌1-10단지 교차로에서 **37분 사이 7명**
- 6월 24일 두 번째 신고(체인·페달) 뒤에야 사라짐 — **12일 동안 서로 다른 73명**

**왜 아무도 몰랐나** — 두 개의 벽
- 신고는 귀찮다: 연달아 포기된 자전거의 **49\~61%** 는 7일이 지나도 신고 없음 (`docs/report.md` 5-3)
- 눈으로는 안 보인다: 공단은 하루 1회 넘게 순회하며 수거의 절반을 신고 없이 찾지만("실제 수거는 신고의 2배쯤"),
  경보가 울린 자전거의 **82\~91% 는 하루 안에 또 빌려진다** — 체인·브레이크처럼 타 봐야 아는 고장 (`analysis/after_alarm.py`)
- 규모: 고장 접수 2024년 **16만 건**, 운영 적자 **127억 원** (`docs/operations.md`)

## 2막 — 발견과 증명 (약 2분, 발표 4\~7장)
**발견** — 73명은 신고하지 않았다. 하지만 모두 **같은 흔적**을 남겼다: 같은 대여소, 3분 안, 300m 도 안 가고 반납. 그 기록은 공개돼 있다.
**규칙 하나** — 서로 다른 두 사람이 연달아 그러면 자전거 탓 (같은 사람 재시도는 생년·성별로 거름)
**공정한 증명** — 기준은 1월로만 정하고 3·6월·대전에 손대지 않고 적용
- 다음 사람도 바로 반납: **35\~44%** (평소 2.5%, 약 14배) — 서울 3달·대전 2달, 약 1천만 건 (`docs/results.md`)
- 신고보다 **20\~25시간 먼저**, 그 사이 한 대에서 평균 4명 헛걸음, 서울 하루 **90\~243명** 막을 기회
**첫 번째 뒤집힘 (실패 → 돌파)** — 실시간 공개 자료는 대여소별 대수뿐이라 정밀도 2% → 포기. 대여이력 API 가 반납 즉시 준다는 걸 찾아 **5분마다 실시간**으로.
**미래를 맞혔다** — 9월 27일부터 실제 운영하며 스스로 채점: 경보 뒤 다음 사람 **1,853명 중 31%** 가 또 바로 반납 — 지난 기록으로 잰 32\~34% 와 같다.

## 3막 — 만든 것 (약 2분, 발표 8\~11장 + 시연)
**시연은 사람 순서로** (영상도 같은 순서)
1. 06:10 순회 직원 — 구를 고르면 먼저 볼 대여소 순서·정비 동선. 자전거마다 **AI 확률과 이유**("72% · 서로 다른 12명이 연달아 반납")
2. 현장 — 의심 자전거 앞에서 탭 한 번(체인·타이어·브레이크·멀쩡함) → 모든 폰의 정비 순위 맨 위
3. 출근길 이용자 — 카메라로 거치대를 비추면 번호판마다 빨강·초록, "타지 마세요"
4. 하루 재생 — 6월 15일 서울, 신고보다 경보가 먼저 켜지는 지도

**기술 (개발 45 를 노리는 세 가지 이야기)**
- **서버 없이 스스로 돈다** — 클라우드 DB 가 5분마다 서울 API 를 받고 SQL 로 연쇄를 센다. 같은 엔진이 파이썬·SQL·스위프트·자바스크립트에 있고 서로 같은 답인지 자동 검사
- **AI 는 이길 때만** — 나무 60그루 모델을 SQL 식으로 DB 안에. 처음엔 확률을 1.5배 크게 잡아 실패 → '얼마나 오래 서 있었나·그사이 외면' 을 넣어 기대=실제. 이유를 사람 말로, 결과로 스스로 다시 배움 (`docs/model.md`)
- **두 번째 뒤집힘 — 무료 DB 에서 버티기** — 10월 2일 밤 무료 클라우드(메모리 0.5GB)가 6시간 멈췄다. 원인을 재서(작업 집합 145MB) 다시 짰고, **같은 답인지 로컬에서 검사**한 뒤 40MB · 한 번 20초로 (`docs/report.md` 6장)

**디자인 (20)** — 토스처럼 화면마다 큰 문장 하나, 로고 그라데이션, 다크 모드, 글자 대비 4.5:1 이상, 웹·아이폰·안드로이드 같은 모양

## 끝 (약 30초, 발표 12장)
- **넓히기** — 대전 타슈는 이미 검증. 그리고 올해 8월 권익위 **'전기차 충전' 민원주의보**(3년 새 1.8배): 앱엔 '사용 가능' 인데 안 되는 충전기를 같은 방법으로 — 연달아 두 번 끊긴 충전기는 다음도 57%(평소 2.7%, 예비)
- **처음으로 돌아가기** — "RIDEY 가 있었다면, 6월 12일 오후 3시 43분, 두 번째 사람이 반납한 그 순간 SPB-69683 은 정비 목록 맨 위에 올랐습니다. 그 뒤 12일 동안 헛걸음한 71명에게, 먼저 알 기회가 있었습니다."
- **신고를 기다리지 말고, 흔적을 읽자.**
