# 현장 조사 절차 (Phase 5) — 사용자가 직접

## 목적
엔진이 "고장 의심" 이라고 할 자전거가 **실제로 고장인지**, 사람이 눈으로 본 것과 맞춰 본다. (지금까지는 "다음 사람도 바로 반납" 을 대리 정답으로 썼다.)
인증키가 없어도 된다: 오늘 본 것을 기록해 두면, **그달 대여이력이 공개되는 다음 달 중순**에 `analysis/field_validation.py` 로 맞춘다.

## 준비
- 맥에서 `python server/app.py` (같은 와이파이). 아이폰 사파리에서 `http://<맥 IP>:8765` → **현장 조사** 탭.
- 아이폰은 https 가 아니면 위치·카메라를 막는다 → 대여소는 **이름으로 찾기**, 자전거 번호는 **직접 입력**(자전거 뒤 흙받이·QR 옆 "SPB-" 번호).
- 서버에 안 닿아도 폰에 모아 두고 다음에 자동으로 보낸다(본 시각 그대로 저장).

## 하는 법 (한 번 나가서 20~30분)
1. 집·학교 근처 대여소 **5곳 이상**, 이용이 많은 곳과 적은 곳을 섞는다.
2. 대여소에 서 있는 **모든 자전거**를 한 대씩 본다(골라 보지 않기 — 치우침 방지).
3. 보는 것: 타이어 바람(엄지로 눌러 봄), 체인 빠짐·녹, 안장 흔들림·빠짐, 브레이크 레버 헐거움, 페달·바구니 파손, 단말기 화면.
   **타 보지는 않는다**(요금·안전). 눈과 손으로만.
4. 상태 버튼 한 번: 멀쩡함 / 타이어 / 체인·기어 / 안장·핸들 / 브레이크 / 기타 고장. 애매하면 메모.
5. 목표: **2주 동안 150대 이상**(고장으로 보이는 게 10~20대는 나오도록).

## 안전·예의
- 차도·자전거도로 위에서 조사하지 않는다. 다른 이용자가 빌리려 하면 비켜 준다.
- 자전거를 분해하거나 거치대에서 억지로 빼지 않는다. 사진은 번호판·사람 얼굴이 안 나오게.

## 끝나면
- 앱의 "조사 기록 CSV 내려받기" → `data/survey.csv`
- 그달 대여이력 공개 후: `python data/download.py`(seq 갱신) → `python analysis/field_validation.py data/survey.csv data/raw/rent_<YYMM>.csv`
- 나오는 숫자: 고장 포착률(사람이 고장이라 본 자전거 중 엔진 경보 비율), 헛경보율, 경보 적중률 → 보고서 9장 "한계" 를 채운다.
