# 현장 조사 절차 (Phase 5) — 사람이 직접

## 목적
엔진이 "고장 의심" 이라고 한 자전거가 **실제로 고장인지**, 사람이 눈으로 본 것과 맞춰 본다.
지금까지는 "다음 사람도 바로 반납" 을 대리 정답으로 썼다 — 심사에서 "진짜 고장이었나요?" 에 답할 숫자가 여기서 나온다.

## 준비 (맥 필요 없음)
- **아이폰 앱** '헛걸음 제로' → 아래 **조사** 탭. 또는 아무 휴대폰 브라우저에서 https://zmflm0110.github.io/bike-doctor/app/ → **조사** 탭.
- 기록은 누르는 순간 **클라우드 DB(Supabase)** 로 간다. 인터넷이 없으면 폰에 보관했다가 다음에 자동으로 보낸다(본 시각 그대로).
- 친구와 나눠 해도 된다 — 각자 폰에서 같은 곳으로 모인다.

## 어디로 갈까
- 앱 **홈 → 지금 (실시간)** 에서 집·학교 근처 구를 고르면 의심 자전거가 있는 대여소와 **막는 동선**(도는 순서)이 나온다.
- 한 번 나갈 때 **경보 있는 대여소 3곳 + 경보 없는 대여소 2곳**. 경보 없는 곳도 봐야 "멀쩡한데 경보" 와 "고장인데 경보 없음" 을 잴 수 있다.

## 하는 법 (한 번 나가서 20~30분)
1. 대여소에 서 있는 **모든 자전거**를 한 대씩 본다 — 경보 자전거만 골라 보지 않는다(치우침 방지). 경보 목록은 **보기 전에 보지 않는다**가 가장 좋다(선입견).
2. 보는 것: 타이어 바람(엄지로 눌러 봄), 체인 빠짐·녹, 안장 흔들림·빠짐, 브레이크 레버 헐거움, 페달·바구니 파손, 단말기 화면.
   **타 보지는 않는다**(요금·안전). 눈과 손으로만.
3. 고장으로 보이면 **사진 붙이기**(선택) — 고장 부위만 가까이. 번호판·사람 얼굴이 안 나오게.
4. 번호(자전거 뒤 흙받이·QR 옆 "SPB-") 넣고, 상태 버튼 한 번: 멀쩡함 / 타이어 / 체인·기어 / 안장·핸들 / 브레이크 / 기타 고장. 애매하면 메모.
   (버튼을 누르는 순간 저장되니 사진·메모를 먼저)
5. 목표: **2주 동안 150대 이상**, 그중 고장으로 보이는 게 15대 이상. 친구 3~5명이면 1주.

## 안전·예의
- 차도·자전거도로 위에서 조사하지 않는다. 다른 이용자가 빌리려 하면 비켜 준다.
- 자전거를 분해하거나 거치대에서 억지로 빼지 않는다.

## 끝나면 (맥에서, 명령 두 줄)
```sh
.venv/bin/python server/supabase_export.py                        # 클라우드 DB → data/survey.csv, data/rescue.csv
.venv/bin/python analysis/field_validation.py data/survey.csv live   # 서울 API 로 그때 기록을 채워 엔진 판단과 맞춤
```
- 나오는 숫자: 경보 적중률(경보 자전거 중 실제 고장)·고장 포착률·헛경보율과 각각의 95% 신뢰구간, 상태별 표 → `docs/field_validation.md`.
- 사진은 Supabase 대시보드 → Storage → survey-photos. 발표에 2~3장.
